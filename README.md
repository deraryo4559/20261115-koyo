# 紅葉ドライブ地図

箱根・芦ノ湖・御殿場、山梨、秩父・多摩の25スポットを、写真と地図から選ぶWebアプリです。

## 開発を始める

Node.js 24 LTS と npm 11 を推奨します（`.nvmrc` を同梱）。

```sh
nvm use
npm ci
npm run dev
```

開発サーバーのURLは端末に表示されます。APIキーやアカウント登録は不要です。地図タイルの読み込みにはインターネット接続が必要です。

```sh
npm run check      # Gitへの混入確認、型検査、テスト、本番ビルド
npm run build      # 静的HTMLの本番ビルド（dist/client/）
npm start          # ビルドしたアプリのローカル確認
```

## 機能

- メインページのリロードから1分後に、3ルートのルーレットを表示。個別アルバムへの移動やリロードでも開始時刻を引き継ぎます。表示はメインページの次のリロードまで1回のみ。初訪問が個別ページの場合は、その読み込み時刻から計測します。別タブ表示中や他のダイアログ表示中は、表示可能になるまで待ちます。×・Escで閉じられます。抽選は1回のみで、回転開始後は再抽選できません。結果の「このルートを見る」から地図を絞り込めます。

- 「すべて」＋3方面の4ボタンで25・5・9・11件を切り替え。
- PCは4列、スマートフォンは2列の写真アルバム。
- 地図のスポット一覧から、各スポットの個別アルバムへ移動。
- 地図のみの構成。ピンはルート別の色で識別し、地図上部に凡例を表示。ピンは集約せず個別に表示し、「すべて」を押すたびに全スポットが収まる縮尺へ戻ります。
- 全25スポット・77枚の紅葉写真とユーザー指定写真。個別ページは `/spots/p01/`〜`/spots/p25/`。
- 写真の拡大、前後送り、左右キー、スマートフォンの横スワイプ、Escapeで閉じる操作に対応。
- 個別アルバムはスポット名と写真を表示。紹介文・アクセス案内・装飾的なコピーは掲載せず、出典は折りたたんで表示。
- 個別アルバムは白に近い背景と中央の見出し、写真の縦横比を保つレイアウト。PCは中央の表紙と2列の写真、スマートフォンは余白を揃えた1列で表示し、元画像より大きく引き伸ばしません。
- 地図のズーム・移動・クラスタ、PCのホバー写真、タップ／キーボードでの選択。
- 写真・地点情報の出典、駐車場や徒歩の確認状況、個別Googleマップへのリンク。
- 表示モードと選択条件を端末内に保存。保存できないブラウザでも利用可能。
- 地図や画像の読み込みに失敗しても、一覧と外部リンクを利用可能。

ルートは方面別の候補グループです。全地点を巡る経路や所要時間は生成しません。

## ディレクトリ構成

```text
app/                   一覧・個別アルバムページと共通レイアウト
src/
  components/          アルバム、地図、詳細、出典表示
  data/                スポット・方面・画像のデータ
  lib/                 表示状態の復元などの処理
  styles/              共通スタイルと地図スタイル
  types/               データの型
public/
  images/spots/        写真、一覧用サムネイル、出典情報
tests/                 データ、状態復元、非公開ファイルの検証
scripts/               Git混入チェックとフック設定
.githooks/             commit・push前のチェック
.github/workflows/     GitHub Actionsによるチェック
requirment/            ローカル専用資料（Git対象外）
```

フロントエンドは React + TypeScript、静的HTMLへのビルドは Vite / Vinext、地図は Leaflet / OpenStreetMap です。ページ構成には Vinext の App Router を使用します。データベースや認証サーバーは使いません。

## GitHubへ載せる前に

`requirment/`、環境変数ファイル、作業ファイル、依存パッケージ、ビルド成果物は `.gitignore` で除外しています。Gitを初期化してから `npm ci` を実行すると、このリポジトリ内に限り `.githooks/` が有効になります。

- commit前：ステージされたファイルに非公開資料が混じっていないか確認。
- push前・CI・ビルド前：Git追跡ファイルに同じ資料が混じっていないか確認。
- 開発サーバー：`requirment/`、`.env*`、`.git/` 等へのファイル配信を拒否。

```sh
git check-ignore -v requirment/requirment.md
npm run check:privacy
git status --short
```

`git add -f` や `--no-verify` で保護を外さないでください。`.gitignore` は既存のGit履歴を消す機能ではありません。別のリポジトリへ移す場合も、非公開資料が追跡されていないことを確認してください。

## GitHub Pagesへの公開

公開先は [紅葉ドライブ地図](https://deraryo4559.github.io/20261115-koyo/) です。

ソースは `main`、公開済みの静的ファイルは独立した `gh-pages` ブランチで管理します。検査・ビルドはローカルの `npm run deploy` で行います。サイトの更新は、検証済みの成果物を `gh-pages` へpushして行います。

- Pagesの公開元：**Deploy from a branch → gh-pages → / (root)**。
- 公開パス：`/20261115-koyo/`（ワークフローの `SITE_BASE_PATH`）。
- 公開対象：`dist/client/20261115-koyo/` の静的ファイルだけ。
- 画像・favicon・JavaScript・CSSは公開パス付きのURLで読み込みます。
- サーバー用コードや `requirment/` はPagesのアップロード対象に含めません。
- 公開ブランチの `.nojekyll` により、静的ファイルをそのまま配信します。

更新は、`main` で変更内容を確認した後、次のコマンドだけで行います。

```sh
npm run deploy
```

`.gitignore` を尊重して公開対象の変更（追加・更新・削除）をすべてステージし、非公開ファイル検査・検証・公開用ビルドに成功した場合だけ、ソースを `Update site for deployment` のメッセージで自動commitし、`main` と `gh-pages` を順にpushします。部分的にステージしたファイルも作業ツリー全体が対象になるため、公開したい変更だけを残して実行してください。検証失敗時はpushせず、変更をステージしたまま停止します。stash・変更の破棄はしません。初回は `.local/pages-publish` を自動作成します。公開内容に変更がなければ空のcommitは作りません。途中で失敗した場合は原因を解消して再実行してください。

`main` がリモートより古い場合や履歴が分岐している場合は停止します。公開用コピーに未コミットの変更が残った場合も停止するため、その内容を確認してから再実行してください。`rsync --delete` の対象は公開ブランチ専用コピーのみです。

自作の `Check GitHub Pages build` は自動起動を無効化しています。標準の `pages build and deployment` は引き続き必要です。送信成功と公開完了は別で、GitHub側の公開処理が請求問題で停止する場合は請求設定の解消が必要です。

同じ公開パスで手元の成果物を確認する場合：

```sh
SITE_BASE_PATH=/20261115-koyo npm run check
SITE_BASE_PATH=/20261115-koyo node scripts/check-pages-artifact.mjs
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist/client
```

`http://127.0.0.1:4173/20261115-koyo/` を開きます。開発時の `npm run dev` は従来どおりルートパスで動作します。

## データと写真の更新

- `src/data/spots.json`：P01〜P25の名称、地点の座標とGoogle Mapsの地点リンク、公式案内、地点の意味、アクセスの確認状況。P20は山梨ルートの新倉山浅間公園。
- `src/data/routes.ts`：3方面の名前と件数。
- `src/data/photos.json`：各スポットの写真配列。先頭が個別アルバムの表紙。パス、サムネイルパス、実寸、代替文、作者、出典、利用条件の表記、季節を記録。
- 画像を追加するときは `public/images/spots/` に置き、出典・利用条件・写真と地点の対応を確認して登録してください。

位置情報の出典は各地点データに記録しています。湖・道路・渓谷等の代表位置を駐車場や車の入口として扱わないでください。変更後は `npm run check` を実行します。

### 現時点の写真の確認状況

P21中津峡・P22鳩ノ巣渓谷（秩父・多摩）、P23名勝・猿橋・P24南伊奈ヶ湖（山梨）、P25大雄山最乗寺（箱根・御殿場）を追加。各3枚の紅葉写真を登録し、南伊奈ヶ湖・大雄山最乗寺はユーザー指定の各3枚に差し替え、3枚目をサムネイルに設定しています。最乗寺の1枚目は指定元の1,024×768pxを維持しています。地点は各施設・渓谷の代表位置として記録しています。

長瀞岩畳・旭日丘湖畔緑地公園・四尾連湖・評議原・大血川・奥多摩周遊道路・秋川渓谷は、ユーザー指定の計22枚へ差し替えています。各スポットの指定順に掲載し、サムネイルは `src/data/covers.json` でアルバムの並びとは別に指定します。

全25地点に2〜4枚、合計77枚の写真を登録しています。評議原（P11）と大血川（P13）の写真も含みます。仙石原すすき草原（P01）は指定された4画像で、すすきの景色を掲載しています。丹沢湖（P02）は指定された3画像、ターンパイク箱根（P04）は指定された2画像を掲載し、それぞれ最初に指定された紅葉写真を表紙・一覧サムネイルにしています。P04の2枚目は指定された夕景写真で、撮影季節は未確認として記録しています。新倉山浅間公園（P20）には構図の異なる紅葉写真を3枚掲載しています。

紅葉期以外の既存写真は差し替えました。御坂峠（P09）はユーザー指定の3画像で、Instagram投稿の富士山と紅葉を表紙にしています。新倉山浅間公園（P20）は五重塔と富士山の全景、紅葉の参道、鳥居越しの富士山の3構図です。芦ノ湖スカイライン（P03）の補助写真には運営会社掲載の秋の芦ノ湖空撮を含みます。写真の撮影場所や対象は写真データと出典一覧に記録しています。写真は過去の景色で、今年の見頃を保証する情報ではありません。

検索で確認した公式・観光・写真サイトの掲載画像と、一部Creative Commonsの画像を使用しています。出典・作者・公開されている利用条件はアプリ内と `public/images/spots/ATTRIBUTION.md` に記載しています。「出典サイト掲載写真」は再利用許諾を確認済みという意味ではありません。CC BY-NC-NDの画像は全体を表示し、トリミングや色調加工をしないでください。

アルバムは元写真の解像度を保ち、一覧・地図プレビューには `public/images/spots/thumbs/` の軽量版を使います。画像は最大長辺1920pxで、一部は元の提供画像が小さいため、その実寸を維持しています。

## 地図について

標準の地図タイルは OpenStreetMap を使用し、帰属表示を常時表示しています。[タイル利用方針](https://operations.osmfoundation.org/policies/tiles/)に沿い、表示に必要なタイルだけを読み込みます。大量アクセスやオフライン配信を行う場合は、対応するタイル提供サービスへ切り替えてください。URLと帰属表示は `src/components/SpotMap.tsx` で管理しています。

## 確認範囲

自動テストは地点数・所属・削除地点の除外、各地点の複数枚の写真と紅葉の表紙・出典情報、保存状態の復元、非公開ファイルを強制ステージした場合の拒否を検証します。実機や通信条件を固定した性能計測、全地点の駐車場・通行規制・営業状況の現地確認は含みません。

ブラウザでは320px・390px・1280px幅の表示、方面ごとの切り替え、フォーカスによる写真プレビュー、選択の固定、地図位置の保持、Escapeと元の写真への復帰、出典ダイアログを確認しました。本番ビルドでも写真・地図の読み込みと方面切り替えを確認しています。個別アルバムの静的HTMLと参照アセットも検査し、スポット一覧からアルバムへの遷移、写真の拡大と前後送り、Escapeで閉じる操作を確認しています。

非公開資料のHTTPアクセスは、開発サーバーで403、本番サーバーで404になることを確認しています。

サムネイルは登録済みの紅葉写真から解像度を優先して選定しています。丹沢湖・大血川・国営昭和記念公園・新倉山浅間公園は指定により維持します。ターンパイク箱根の高解像度の補助写真は季節未確認の夕景のため、紅葉のサムネイルを維持しています。
